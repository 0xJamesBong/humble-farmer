# Contract boundary

Python (strategy-engine) writes; Rust (execution-engine) reads. These files are the only handshake between the two engines.

## strategy_spec.json

Produced by the Python strategy engine. Schema:

- **version** (int): Contract version; must be 1 for MVP.
- **generated_at_utc** (string): ISO 8601 UTC time when the spec was generated.
- **period_4h_end_utc** (string): ISO 8601 UTC time of the 4H bar this spec applies to.
- **leverage_allowed** (bool): Must be false for MVP.
- **target_weights** (object): Symbol → weight (0–1). Weights should sum to 1.0. Symbols (e.g. USDT, SOL, WBTC, WETH) are resolved to Solana mints via `assets_map.json`.

## assets_map.json

Static map maintained in repo (not generated by Python). Maps symbol → `{ "mint": "<base58>", "decimals": <int> }`. Execution engine uses this to resolve target_weights to on-chain mints. Add or update entries when new assets are supported.
